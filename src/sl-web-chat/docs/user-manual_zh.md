# sl-web-chat · 用户手册

本手册面向**最终用户**：怎么装上、配上、用顺。开发者若要了解能力契约与实现细节，请读 `README_zh.md` 与 `concept_zh.md`。

---

## 1. 安装与部署

sl-web-chat 反着来：**它就是一个文件。**

- **零安装**：没有安装包、没有登录、没有外部依赖库。
- **双击即开**：直接双击 `sl-web-chat.html`，浏览器占满全屏，打开即对话。
- **同源托管（推荐）**：把 `sl-web-chat.html` 放到任意静态服务器（如 `http://127.0.0.1:13155/`）下打开，可彻底免跨域，体验最稳。

它**不绑定任何平台**——你把后端地址填进去，它就去问那个后端；回复里的资源直接内联渲染，不跳走。

> 启用 synth-loop 能力（数据面、闸）时，会话由前端自动管理 `x-synthloop-session-id`，无需你手填。

## 2. 配置后端

点右上角 ⚙️ 打开配置面板。

### 2.1 Base URL（聊到哪）

- **相对路径**（默认 `/v1/chat/completions`）：适用于同源托管场景，浏览器自动拼成完整地址。
- **完整 URL**（如 `http://127.0.0.1:13155/v1/chat/completions`）：适用于后端与页面不同源，或你直接 `file://` 双击打开时。

> `file://` 双击打开时相对路径无法解析，**必须用完整 URL**。

### 2.2 Headers（聊天鉴权）

以 JSON 形式填写，原样附加到对话 POST 与上传请求上。默认含 `{"Content-Type": "application/json"}`；API Key、自定义鉴权头都走这里。

### 2.3 Model

填入你的模型名（如 `gpt-3.5-turbo`）；留空则用默认值。

> 请求体固定带 `max_tokens: 1000` 与 `temperature: 0.7`（页面内置常量，不在界面暴露）。

### 2.4 启用 synth-loop 服务（可选）

勾选后开启**数据面**（上下文长期/临时区）与**闸管理**（相位三闸、推理闸）。不勾选时行为与纯 OpenAI 聊天完全一致，向后兼容。

---

## 3. 头部控件

`⚙️ 配置` 旁有几个常驻控件：

- **语言下拉（`langSelect`）**：遍历语言注册表（当前中文/英文），切换界面文案（仅外壳，回复与输入不变）。双包可切；单语包自动隐藏该下拉。
- **数据面板（📂 Data）**：打开/关闭常驻数据面板，管理长期上下文（详见 §4.3）。
- **上传（📎）**：喂入文件作为多模态内容一起发给后端。

## 4. 日常使用

| 动作 | 怎么做 |
|---|---|
| 开始对话 | 打开页面即可，无需注册登录 |
| 发送消息 | 输入框打字，`Enter` 发送，`Shift+Enter` 换行 |
| 喂资料 | 点 📎 上传图片 / 视频 / 音频 / 文件，作为多模态内容一起发往后端的模型 |
| 看回复 | 文字逐字流式出现；若模型回了一组资源链接，页面直接内联成画廊，不跳走 |
| 清屏 | 点 `Clean`，消息清空、历史重置、会话重置 |
| 管理数据面 | 点 📂 Data 打开常驻面板，增删长期上下文 |
| 触发相位闸 | 发送含 `<tc-phase>` 的请求，进入相位三闸流程 |

### 4.1 相位三闸怎么走（pk 闸）

发送 `<tc-phase>…</tc-phase>` 后，一次提问按下面三步流转，每步都弹一张闸卡片，你点头即可推进：

```
发送相位请求
   │
   ▼
① 计划确认（阶段 1/3）→ 确认 → 展示路径
   │
   ▼
② 路径确认（阶段 1/3）→ 确认 → 执行
   │
   ▼
③ 审批（阶段 2/3）→ 确认 → 全部相位完成，报告已生成
```

- 每张卡片可点「确认」推进；「驳回」+ 意见、「中止」可中断当前步骤。
- 闸卡片上的产物视图会展示对应阶段的 artifact（计划摘要 / 路径信封 / 结果）。

### 4.2 推理闸怎么走（ck 闸）

当后端把推理上下文 park 住（响应带 `gate=pending`）时，会弹一张**推理闸卡片**：

- 展示被 park 的上下文 JSON；
- 你可编辑后点「带编辑继续」（amend），或「驳回」「中止」；
- 放行后进入下一轮，后端基于修正后的上下文输出。

### 4.3 数据面说明

- **长期区 `longdata`**：存后端，跨会话持久。在 📂 Data 面板里「+ 添加」类型（doc / memory）与内容，可删除。适合喂给后续所有对话的固定上下文。
- **临时区 `packets`**：随当次对话发送，一次性的上下文。通过 📎 上传文件或指定内容，作为本轮要发的临时上下文。

> 数据面是"喂给模型的上下文"，与闸卡片里的"上下文编辑"是两回事：前者是数据，后者是被 park 的推理上下文。

## 5. 故障排查

### 5.1 连不上后端

前端捕获到网络层失败时会给出可操作提示：

1. **后端未启动 / 地址不可达** → 确认后端是否已跑，或地址是否正确。
2. **`file://` 跨源被 CORS 拦截** → 把地址里的 `localhost` 改为 `127.0.0.1`。
3. **`localhost` 被解析到 IPv6 `::1` 而服务只听 IPv4** → 同样改用 `127.0.0.1`，或同源打开。

### 5.2 闸相关

- **相位/推理闸无响应**：确认已勾选「启用 synth-loop 服务」，且后端实现了 `synth_pipeline` / `gate` 契约；后端未实现时该项能力不可用，前端不会渲染对应卡片。
- **确认后报 400（`unknown pipeline_id`）**：相位已结束，之前触发的确认无效。重新发送一个 `<tc-phase>` 请求开启新一轮即可。
- **数据面不生效**：确认已建立会话（先发一条普通消息再操作数据面板）；长期区增删以会话为边界，`Clean` 后需重新建立。

### 5.3 本地演练

没有真实后端时，可起 `mock-server`（`python main.py`，监听 `:13155`）全功能演练；其契约与 synth-loop 端点 1:1 对齐。

## 6. 已知限制（诚实清单）

- **仅 OpenAI 风格下游**：不支持 Anthropic 等其它协议。
- **无系统提示预注入**：对话历史从空开始，仅启用 synth-loop 时注入轻量语言指令，不膨胀上下文。
- **`max_tokens` / `temperature` 为内置固定值**：当前不在配置界面暴露。
- **单文件 HTML 不执行 LLM 生成的 JS**：指令/产物以文本原语消费，不 eval。
- **相位与闸依赖后端字段**：后端未实现 `synth_pipeline` / `gate` / 数据面端点时，对应能力不可用（不渲染或提示），不影响聊天主链路。

## 7. 安全收尾：责任在配置者一侧

sl-web-chat 把「掌控感」交还给你，但也意味着**数据流向由你填的后端决定**。它自身不收集数据、不内置模型，但请对你接入的服务保持基本警惕：

- API Key 写在聊天 Headers 里；
- 长期/临时上下文发给哪个后端由你配置；
- 模型回复会渲染什么网页由你的后端输出决定。

前端已对资源 URL 做 `http/https` 校验、对 iframe 加 `sandbox`。但 sandbox 不是银弹——请在你自建后端的输出层多做一层把关。
